# GitHub Star 时推荐 Lists

给 GitHub 的 **Lists**（星标收藏夹）加一个"顺手归类"的油猴脚本：你点 Star 的时候，它先读懂这个项目是做什么的，然后告诉你该放进哪个已有 List；如果没有合适的，就直接给出该新建哪个 List，并一键完成。

不需要再去猜"这个仓库到底该塞进哪个收藏夹"，也不会因为嫌麻烦而把所有东西都堆进 `Other`。

## 一键安装

点这个链接，Tampermonkey 会弹出安装页：

```
https://raw.githubusercontent.com/baokamaka/github-star-lists-advisor/main/github-star-lists-advisor.user.js
```

手动安装：Tampermonkey → 添加新脚本 → 把 `github-star-lists-advisor.user.js` 全文粘贴进去 → `Ctrl+S`。

需要浏览器里装了 [Tampermonkey](https://www.tampermonkey.net/)（Violentmonkey 也可，用到的 GM API 都在标准集合里）。

## 怎么用

| 入口 | 说明 |
|---|---|
| **点 Star** | 在仓库页点 Star 后，按钮下方自动浮出推荐面板 |
| **✦ 归类推荐** | 仓库头部（Star 旁）的常驻按钮，点一下打开、再点收起；不点 Star 也能随时看推荐 |
| **✦ 批量归类未分组** | 你自己的 `https://github.com/<你>?tab=stars` 页面上的常驻按钮，扫描没进任何 List 的 star 并给出整批计划 |
| **`Alt` + `L`** | 强制重新分析当前仓库（会忽略"只在没匹配时弹出"等抑制设置） |
| 油猴弹窗菜单 | 同一批入口的菜单版：重新分析本页 / 本次会话停止自动弹出 |

批量面板里可以逐条勾选，然后 **依次应用所选** —— 它会依次跳转每个仓库页、驱动 GitHub 原生的 Lists 面板完成加入或新建，中途关掉页面就停。

## 推荐是怎么来的

三层，全部在本地算，不调外部服务：

1. **内置类别词典**（21 个类别，中英别名 + topic 映射）
   仓库的 topics / 描述 / README 先归到类别（`AI / LLM`、`命令行工具`、`音视频与媒体`…），你的列表名也解析成类别。同类强加、异类压到四成。
2. **词面证据 + 区分度过滤**
   topics、描述与列表名/列表描述的重叠词计分；一个词只要出现在 **2 个及以上**列表的内容里就不算证据（否则 `gadget` 这种大杂烩列表会跟所有仓库"匹配"）。
3. **自学习签名**
   抓取每个列表里已有仓库的名称 + 描述 + 语言，反推这个列表的实际口味。列表名叫 `收藏`、`gadget` 这种看不出类别的，靠这一层也能归对。

另外两条规则：

- **兜底列表永不进推荐结果** —— `Other / misc / 杂项 / 未分类 / inbox` 这类名字被识别为垃圾抽屉，不会被"推荐加入"，避免继续往里堆。
- **类别已被现有列表覆盖时不再建议新建同类列表** —— 你有 `AI` 就不会再劝你建 `AI agents`。想为同一领域开第二个列表，靠 LLM 层或手动。

### 新建列表的命名

默认**跟随你现有列表的命名风格**（中/英、大小写、多词分隔符都从你的列表名学）。也可以在设置里强制中文或英文。中文模式下拿不到中文类别名时统一加「相关」，不会吐一堆英文。

## LLM 增强（可选，默认关闭）

规则层是打底，LLM 是锦上添花：它能读懂 README 并给出更准的归属和更自然的列表名。**不启用也完全可用**。

设置里选一个预设服务商，Base URL 和模型名会自动填好（端点均查证过）：

| 服务商 | Base URL |
|---|---|
| DeepSeek | `https://api.deepseek.com/v1` |
| Kimi（月之暗面） | `https://api.moonshot.cn/v1` |
| 智谱 GLM（国内） | `https://open.bigmodel.cn/api/paas/v4` |
| 智谱 GLM（Z.AI 国际） | `https://api.z.ai/api/paas/v4` |
| 通义千问（阿里云百炼） | `https://dashscope.aliyuncs.com/compatible-mode/v1` |
| 腾讯混元 | `https://api.hunyuan.cloud.tencent.com/v1` |
| 硅基流动 SiliconFlow | `https://api.siliconflow.cn/v1` |
| 火山方舟（豆包） | `https://ark.cn-beijing.volces.com/api/v3` |
| Groq | `https://api.groq.com/openai/v1` |
| OpenRouter | `https://openrouter.ai/api/v1` |
| Ollama（本地） | `http://localhost:11434/v1` |
| LM Studio（本地） | `http://localhost:1234/v1` |

- 模型名过时是常见坑，所以有 **拉取模型列表** 按钮：直接 `GET {base}/models` 把你账号真实可用的模型 ID 填成下拉选项。
- **测试连接** 按钮会当场告诉你通不通、报什么错。
- 任何一家只要兼容 OpenAI 的 `/chat/completions` 就能用，选"自定义"填 Base URL 即可。

### 常见报错

| 报错 | 含义 | 怎么办 |
|---|---|---|
| `403 Free quota exhausted` | **不是配置错** —— 请求已经打到模型并被识别，是账号免费额度用完且控制台开了"仅使用免费额度" | 充值，或在控制台关掉那个开关，或换一个有额度的模型 |
| `401` | Key 不对或已失效 | 重新创建 Key |
| `404` | Base URL 路径或模型名不对 | 用"拉取模型列表"确认可用 ID；注意 Groq 必须带 `/openai/v1` |
| `400 ... response_format` | 该端点不支持强制 JSON 输出 | 脚本会自动去掉该参数重试一次，一般无需处理 |
| `请求失败（网络或被拦）` | 跨域被拦或需要代理 | 确认脚本管理器给了 `GM_xmlhttpRequest` 权限（本脚本已 `@grant`） |

LLM 失败时面板会退回规则结果，并在进度条那一行标出"已退回规则结果"，不会静默变傻。

## 设置项

| 项 | 默认 | 作用 |
|---|---|---|
| 匹配阈值 | `0.3` | 低于此分不推荐已有列表，转为建议新建 |
| 最多建议数 | `3` | 面板里最多列几个已有列表 |
| 推荐列表名语言 | 自动 | 新建建议用中文 / 英文 / 跟随现有列表 |
| 批量上限 | `30` | 一次批量最多处理多少个未分组 star |
| 列表内容缓存小时 | `24` | 列表内容（自学习用）的缓存时长 |
| 显示按钮 | 开 | 仓库头 + stars 页的常驻按钮 |
| 分数不够时读列表内容辅助匹配 | 开 | 关闭则跳过深匹配和自学习，更快但更粗 |
| 只在没有匹配到现有 List 时弹出 | 关 | 开启后能明确归入已有列表时不打扰你 |
| 启用 LLM 增强 | 关 | 见上 |
| 超时秒 / 结果缓存小时 / Temperature / Max tokens | `30 / 24 / 0.2 / 900` | LLM 调用参数 |

## 隐私与安全

- 读取只走**你自己浏览器里 GitHub 同源页面已经在用的接口**：`/{owner}/{repo}/_header/lists`、你的 stars 页和列表页。没有第三方服务器。
- 写入**全部通过驱动 GitHub 原生的 Lists 面板完成** —— 脚本不构造任何未公开的写请求。
- 只有在你启用 LLM 并填入 Key 之后，才会把"仓库名 / 描述 / topics / README 摘要 + 你的列表名"发给该服务商。仓库是私有的话，这些文字会离开本机，请自行判断。
- API Key 以**明文**存在脚本管理器自己的存储里（Tampermonkey 的存储库）。共用电脑时注意。

## 已知限制

- **依赖未公开的内部结构**。GitHub Lists 至今是 public preview 且没有官方 API，`_header/lists`、`data-testid`、面板 DOM 都可能随时变更。脚本按"探测失败就降级"设计：读不到就提示手动，不会写坏数据。
- **把仓库加入 List 会自动 Star 该仓库** —— 这是 GitHub 自己的行为（实测确认）。
- 判断"已分组"依据各列表页可见的仓库，**超长列表若被 GitHub 截断会漏判**。
- 深匹配冷启动要抓若干页面（每个列表页约 600KB），首次慢一些；结果缓存 24 小时。列表超过 15 个时只读前 15 个，面板上会写明"另有 N 个未参与匹配"。
- 只在**仓库首页**和**你自己的 stars 页**工作；搜索结果页里的 Star 按钮不接。
- 面板配色用主题无关的写法（透明底 + 继承文字色），跟随 GitHub 明暗主题。

## 调试

脚本在页面上暴露三个全局函数，F12 控制台可用：

```js
gsaDiag()            // 当前仓库信息、列表清单、每个列表的打分与理由、配置、错误
gsaRun(true)         // 不点 Star 也跑一遍推荐（true = 强制，忽略抑制设置）
gsaBatch()           // 在 stars 页打开批量面板
```

GitHub 结构变了导致不工作时，把 `gsaDiag()` 的输出贴出来即可定位。
